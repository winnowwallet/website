01 / A simpler structure

State. Events.
A clear next step.

LeanNative uses a model, update and view pattern. Events enter the app; update logic decides how the model changes; the view describes what should appear.

The structure gives developers a concrete place to reason about behavior and prove selected properties, while keeping the visible interface native.

02 / Mathematical checks

Prove key properties.
Test the experience.

Lean’s proof checker can verify a theorem about the program under its stated definitions and assumptions. Compilation also produces code the app can run.

Mathematical checks work alongside app testing, including native rendering, networking and device behavior.

For Winnow, recorded journeys complement proofs by exercising the app’s visible flows in an iPhone simulator.

03 / On Apple platforms

Real controls.
A different foundation.

LeanNative supports native iOS and Mac interfaces. A generated Objective-C bridge connects Lean code to Apple’s UI and platform capabilities.

Winnow uses that bridge to connect its wallet logic to the iPhone interface. The framework remains a separate open-source project with its own examples and documentation.
